# MVaaC 迭代需求计划

日期：2026-10-02。状态：本轮已实施并验收；阶段提交、设计决策与测试证据见 [实施记录](mvaac-design.md)，当前使用契约见 [组件指南](../docs/mvaac.md)。

## 1. 目标与交付边界

将 MVaaC 从基本 demo 完善为真正可复用、文档清晰的框架无关 TypeScript 组件库，首先服务于基于 CodeMirror 的分屏 Markdown 编辑器，后续支持 VS Code 插件独立接入预览组件。

本轮交付 `@markview/viewer` 与 `@markview/editor`，并通过独立包提供字体和浏览器资源接入辅助。编辑器应具备基本完整的编辑、实时预览与自动双向滚动同步能力。允许调整现有 API、模块结构和包组织。

本轮不实现 VS Code 插件、React/Vue 包装、文件管理或 PDF 导出。点击预览定位源码不作为本轮必需功能：同步滚动自动发生，无须点击介入。Markview 原生应用保持只读定位；编辑能力归属于新的 Web editor 包。

## 2. 当前基础与缺口

以下保留实施前的代码与文档静态检查结果；当前行为以组件指南和验收记录为准：

- 现有 `@markview/web` 包包含底层 `Markview`、渐进排版句柄与负责帧循环和输入的 `CanvasReader`。
- 已有选择复制、文档内锚点、折叠内容、宽内容横向滚动及宿主管理的异步图片机制，并有对应 Playwright 测试。
- 核心层块与行内节点携带源码范围，排版快照保留块的源码范围及位置；完整双向映射仍需补齐和验证。
- 核心层已有 `Document::outline()` 与标题锚点，但 TypeScript 公共接口尚未暴露 TOC。
- 字体目前只接受 OpenType、TrueType 及字体集合；初始化后的字体配置全局共享。
- SVG 图片已有浏览器解码路径和测试，不能据此宣称内嵌 SVG 等场景均已支持。

既有契约见 [MVaaC demo contract](../docs/mvaac-web-demo.md)。其中针对初始 demo 的范围排除项不用于限制新迭代；实施时需同步整理文档，明确哪些旧约定被替代，避免多份冲突的契约。旧契约已标为历史参考，并链接到本轮权威指南。

## 3. 包职责

| 包 | 职责与边界 |
| --- | --- |
| `@markview/viewer` | 独立预览组件；渲染、阅读交互、TOC、源码映射、滚动控制与通知、字体及资源注入、生命周期。可独立供 VS Code 插件使用。 |
| `@markview/editor` | 基于 CodeMirror 的分屏编辑组件；组合编辑器与 viewer，协调内容更新、自动双向滚动同步与分屏布局。 |
| `@markview/fonts`（暂定名） | 字体 URL/字节加载、字体集描述和缓存；提供显式使用的 CDN 接入便利性，不携带文本字体。 |
| `@markview/resources`（暂定名） | 浏览器图片加载与解码、相对路径解析、请求配置等辅助；宿主仍可完全接管资源解析和交付。 |

通过 DOM 容器挂载使用，不依赖前端框架。viewer 不依赖 CodeMirror，字体与资源辅助包应按需使用。基础包不默认绑定 CDN 或发起隐式字体下载。

实际内部模块划分、两个辅助包的最终名称以及是否保留 `@markview/web` 兼容入口属于实施设计；必须在迁移文档中说明结果。WASM 与资源文件部署方式需对下游构建工具明确可用。

## 4. 核心需求：源码映射与自动双向同步

### 4.1 行为

- 用户滚动编辑器，预览自动跟随对应源码内容；用户滚动预览，编辑器自动跟随对应源码内容。
- 以源码位置和渲染几何为映射基础，不采用全文滚动百分比作为主要同步方式。
- 程序产生的跟随滚动应与用户输入可区分，不形成反馈循环；任意一侧的新用户操作应接管同步。
- 连续编辑、窗口缩放、字体变化和异步图片到达引起重排时，尽量保留正在阅读的内容位置，避免跳至顶部或跟随旧文档。
- 渐进排版期间，目标尚未排出时允许等待并在可定位后跟随；新的用户操作或文档替换可以取消旧目标。不得为同步强制同步完成整篇排版。
- 同步不得依赖额外点击、改变普通文本选择行为或抢夺编辑器焦点。

### 4.2 viewer 对宿主的能力

公开源码位置到预览位置、预览位置到源码位置的查询能力，以及按源码位置定位预览、监听阅读位置变化的接口。编辑器内部同步必须使用这些公共能力，避免仅 demo 可用的私有通道。

接口需明确文档版本、源码坐标和几何坐标的语义。建议 TypeScript 使用 UTF-16 offset，与 CodeMirror 的位置约定一致；Rust 的 UTF-8 字节范围在边界转换。若暴露行列坐标，必须说明起始基数及列的计量单位。文档版本不得与同一文档多次发布的排版 revision 混淆。

普通段落和代码块的长内容需要可支持行内/行级跟随，不能只映射到顶层块开头。列表、引用、表格等嵌套内容应定位到合理的内部单元；图片、公式等整体内容映射到其源码范围。空白行、不可见语法和折叠内容需定义确定的降级行为。

折叠内容的同步展开策略、视口采用的参考位置及映射精度应在实施设计中明确，并通过实际分屏样例验证；不得宣称所有渲染字符与源码字符一一对应。

## 5. 核心需求：TOC API

- 对宿主返回按文档顺序排列的标题列表，至少包含标题文本、层级、锚点和源码范围。
- 完整 TOC 在解析完成后即可取得，不要求全部排版完成；文档更新后提供对应新版本的数据。
- 提供标题跳转能力，支持目标尚未排版的情况，以及当前阅读章节的查询或变更通知。
- 建议标题跳转可展开目标所在的折叠内容；具体行为必须明确并测试。
- 正确处理重复标题、跳级标题、中文标题、无标题文档及容器内部标题。
- viewer 提供数据与导航能力，宿主拥有目录界面；editor 提供可配置的基本目录面板。

## 6. editor 的基本完整性

以 CodeMirror 为编辑基础，提供 Markdown 高亮、常用编辑快捷键、撤销重做、缩进和列表续写。默认分屏包括编辑区与预览区，具备实时内容更新、自动双向滚动同步和可拖动分隔线。

公开设置/读取内容、内容变更通知、配置、销毁及必要的 CodeMirror 扩展接入能力。支持多实例，主题与布局可配置；组件样式应避免污染宿主页面。新建、修改、关闭和重复挂载均应有明确生命周期。

最终示例必须消费构建后的包入口，展示 CodeMirror 编辑、双向同步、TOC 及独立字体/资源包组合。使用方应能按文档以少量接入代码得到可工作的分屏编辑器。

以上为讨论中的基本功能范围；工具栏按钮清单、搜索替换等额外编辑功能不默认扩展为独立交付要求。

## 7. 字体与资源

### 7.1 字体所有权

viewer 和 editor 不内置文本字体，保留 KaTeX 数学字体例外。宿主通过字体字节或 URL 显式提供字体；不同 viewer 可使用不同字体集，同一字体集可共享复用，避免全局首次初始化锁定全部实例。

Web 场景通过独立字体包接入 CDN 或自托管字体。未来 VS Code 场景由插件宿主发现并读取系统字体，再向 viewer 提供字节；Webview 中的 WASM 不负责系统字体发现。

第一轮支持直接字体文件 URL、字节和显式字体集配置。自动解析 CDN `@font-face` CSS、按字符范围下载分片和运行中动态补字留待后续。

### 7.2 WOFF/WOFF2

加入 WOFF/WOFF2 解码至引擎可读 OpenType 数据的能力，作为 Rust 可选 feature；官方 Web/WASM 构建启用，自定义构建可关闭。构建 feature 与运行时选项必须区分，发布后的 WASM 不能通过 JavaScript 配置移除解码器体积。

解码放在 WASM 字体输入边界，下载、字体集组织和缓存由字体包负责。解码依赖暂不锁定，需验证 WASM 构建、格式覆盖、许可证、产物体积与初始化成本。现有 OTF/TTF/TTC 输入继续可用，错误字体应产生可识别的初始化/加载失败。

参考：[WOFF2 规范](https://www.w3.org/TR/WOFF2/)；[wuff 解码库文档](https://docs.rs/wuff/latest/wuff/)（候选，不代表选型已确定）。

### 7.3 资源

资源辅助包提供浏览器 URL 加载、图片解码和相对路径基准配置，允许传入请求配置。viewer 保留宿主接管请求、取消、失败、缓存及资源结果交付的能力。

文档需说明资源加载与排版完成的区别，以及资源到达导致重排时的位置保持和旧请求取消行为。未来 VS Code 插件可替换本地路径解析与资源传输，不要求组件读取本地文件系统。

## 8. SVG 与内容完成度

SVG 纳入本轮计划，但排在同步、TOC 和库工程化之后。先区分并验证 SVG 文件引用、data URL、字节解码、内嵌 `<svg>` 以及包含相对资源引用的情况，避免将已有静态图片解码等同于全部 SVG 支持。

用户已确认：本轮支持 SVG 文件引用、data URL、宿主字节和内嵌 `<svg>` 静态图片；内部相对外部资源引用不支持，Mermaid 留待后续。已实现相应支持矩阵、限制与失败表现。

对其他 Markdown 内容建立简明支持矩阵，至少覆盖段落、标题、嵌套列表/引用、代码、表格、公式、图片、链接与折叠内容；优先修复阻碍编辑预览与同步的问题。

## 9. 工程与文档要求

- 明确公开 API 与内部实现、底层引擎与组件输入处理、宿主同步职责和资源职责，避免重复排版/输入逻辑。
- 包入口、类型声明、依赖关系、WASM 与静态资源产物组织一致；提供构建后包的实际接入验证。
- 文档包括快速开始、每个包的职责、公共 API、CodeMirror 同步示例、独立 viewer 接入、TOC、字体/资源、能力边界、迁移说明及构建测试流程。
- 快速开始不得依赖未说明的全局变量、demo 专属接口或隐式字体资源；解释字体与资源包如何组合。
- 按本轮最终实现整理旧契约及 README，建立清楚的权威入口；避免新 API 与旧文档互相矛盾。
- 更新简洁 changelog，遵守仓库格式、lint、测试及 Rust 改动前构建并备份基线二进制的要求。

## 10. 实施顺序

1. **P0：契约与工程设计。** 定义包边界、源码坐标/版本、映射与滚动事件、TOC、实例字体配置及迁移方案。
2. **P0：映射、同步与 TOC。** 补齐 viewer 公共接口，基于 CodeMirror 验证自动双向同步，再完善目录数据与导航。
3. **P0：完整组件与文档。** 整理 viewer/editor、默认编辑体验、挂载销毁、主题布局、构建产物与接入示例。
4. **P1：独立接入辅助。** 字体/资源包、实例字体集和 WOFF/WOFF2 支持；与组件工程整理协同完成。
5. **P2：SVG 与剩余完成度。** 确认 SVG 子范围，补齐支持、限制文档和内容回归。

优先级表示推进顺序；已确认的字体与资源工作仍属于本轮交付，不因列为 P1 自动移出范围。未确认的 SVG 子范围须在实施前补齐。

## 11. 验收标准

| 场景 | 验收结果 |
| --- | --- |
| 独立接入 | 按文档从构建后的包挂载 viewer 或 editor；显式组合字体/资源后可用，不依赖 demo 私有代码。 |
| 自动双向同步 | 滚动任意一侧，另一侧跟随相同源码内容，无额外点击、循环振荡或焦点抢夺；长段落和长代码块可跟随内部位置。 |
| 非等高内容 | 图片、表格、嵌套容器和折叠内容不导致全文百分比式累计错位；降级行为有文档。 |
| 编辑与重排 | 连续编辑、中文输入组合过程、宽度变化、异步图片加载及渐进排版期间保持合理阅读位置，旧版本通知不驱动新文档。 |
| Unicode 与行结束符 | 中文、emoji、组合字符、LF/CRLF 场景的源码坐标正确；UTF-8 与 UTF-16 转换不造成偏移。 |
| TOC | 文档更新后获得完整新目录；重复标题可区分，章节通知与导航一致，未排版目标可等待定位。 |
| 字体 | 不内置文本字体；多实例可用不同字体集；官方 WASM 可解码 WOFF/WOFF2，原有格式不回归。 |
| 资源与生命周期 | 相对路径可由宿主确定；替换文档/销毁取消旧请求，重复挂载与多实例无事件或资源泄漏。 |
| 工程交付 | 类型、构建、lint 和相关集成测试通过；公共文档与实际导出一致，迁移边界明确。 |

主要采用集成测试验证真实 CodeMirror/viewer 行为；源码转换等必要算法使用少量针对性测试。沿用现有 Web 回归测试，并在涉及渲染时验证实际画面。性能指标在基线测量后制定，不以当前未经测量的数值作为承诺。

## 12. 已确定的实施设计与后续能力

- SVG 按第 8 节确认范围交付；Mermaid 留待后续。
- 辅助包定名 `@markview/fonts`、`@markview/resources`；保留 `@markview/web` 兼容重导出，API 与迁移见组件指南。
- 普通同步保留折叠状态，TOC 跳转展开目标；以顶部行源码位置及行内垂直比例为参考，映射精度与确定性降级见源码 API 指南。
- 采用可选 Rust `wuff` 解码；官方启用、自定义可关闭，格式验证、许可证与体积/启动成本见字体测量文档。

以上实施结果满足本轮核心目标：框架无关、CodeMirror 分屏、自动双向同步、宿主 TOC API、认真整理的可复用库，以及独立提供的字体与资源辅助。
